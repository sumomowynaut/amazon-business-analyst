# 数据识别与口径管理

## 建立来源清单

为实际参与分析的每份文件记录：文件名与工作表、用户说明的来源、导出时间（如有）、覆盖期间、站点、币种、时区、每行含义、候选主键及主要限制。用户提供的文本同样需要标明覆盖对象和时间。未知项写明未知，不从文件名推断账户或市场身份。

常见数据及限制：

| 数据 | 可能回答的问题 | 使用前需要确认 |
| --- | --- | --- |
| 业务报告、订单明细 | 销售、流量、转化和商品贡献 | 订单与商品件数、父子体、订单日期与发货日期、B2B列是否为总量的子集 |
| 广告活动、投放、搜索词报告 | 费用、归因表现、覆盖和投放差异 | 广告类型、归因窗口、点击与浏览归因、推广商品与购买商品、报告粒度 |
| 库存、补货和库龄报表 | 缺货、库存占用及补货约束 | 快照时点、可售与预留、在途状态、补货提前期、缺货期需求截断 |
| 结算、交易、成本与退款报表 | 现金流、费用、利润与退货影响 | 收入确认、结算跨期、费用正负号、税费、退款归属、成本完整性 |
| 市场、竞品及关键词导出 | 样本内竞争、价格带、需求与词覆盖 | 实测或估算、覆盖范围、采样周期、排名采样方式、单位及版本 |
| 评论、问答与用户调研 | 反馈主题、使用障碍及需求线索 | 抽样方式、变体、重复记录、语言、是否包含完整评论与日期 |

这些是识别线索，不构成必须出现的字段清单。不同站点、广告类型和导出版本可能改变字段及含义。

## 字段映射

保留原列名，建立“原列名 → 分析字段 → 定义 → 单位 → 转换规则”的映射。`Sales`、`销售额`、`Revenue`不能仅凭名称视为相同指标；广告归因销售、Ordered Product Sales与结算收入需要分别保留。

- 把ASIN、SKU、活动ID和订单ID作为字符串，保留前导零及大小写。标题或显示名称不适合充当唯一键。
- 日期解析明确日/月顺序与时区；`03/04`无法确认时不要猜。期间结束日是否包含在内要统一。
- 识别小数点、千分位和币种符号。金额括号是否表示负数，应结合来源说明验证。
- `12%`与`0.12`可按确认的规则统一；裸数`12`可能是12%或12倍，不自动判断。
- 零、空白、未覆盖、不适用分别保留。没有展示记录不等于没有需求。
- XLSX公式单元格的缓存可能缺失或过期；不要将空缓存当作零。要求重算导出或使用原始输入重新计算。
- 对文本中的换行、编码和重复内容作可复现处理；不要删掉改变情绪或产品用途的词。

## 合并与去重

1. 为每张表写出业务主键，例如“站点＋日期＋子ASIN”，不要默认ASIN跨站点唯一。
2. 检查主键是否唯一；重复行可能是多个订单项目、费用类型或广告位置，先确定含义。
3. 将两张表整理到兼容粒度，再合并。多对多关系需要明确分摊规则，否则保留分表比较。
4. 合并前后核对行数、销售额、花费与订单数；记录未匹配的键及占比。
5. 父体汇总与子体明细不可相加；汇总行与详情行不可相加。广告活动、广告组和搜索词的总量不能跨层级叠加。
6. 重叠期间的多次导出须处理覆盖关系。增量、快照和最新重述数据不能使用同一种去重方式。

若搜索词报表未覆盖所有流量或因阈值省略记录，不能以其明细合计替代广告总体。先与同口径控制总计核对，再说明覆盖缺口。

## 对齐与保存

选择等长、完整且具有业务可比性的期间。近期归因尚未成熟时，使用成熟窗口或明确标记未成熟数据。缺少汇率时分币种报告，不直接相加。

库存快照用于时点比较，不跨日求和为库存总量。价格、排名与比率通常也不能按流水金额那样相加。

原始文件保留不变。工作文件写入任务专用目录，记录关键转换和校验摘要。正式报告使用可公开的文件标识，避免暴露本机路径、订单客户信息或无关账号标识。
