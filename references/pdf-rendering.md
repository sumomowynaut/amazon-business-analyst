# PDF 生成与检查

`scripts/render_report.py` 把一份已经核对过的报告 JSON 排成 PDF。它不读业务数据、不计算指标、不推断原因；分析结论由分析师写入 JSON，脚本只负责呈现。

## 依赖

- Python 3.9 及以上。
- `reportlab`（见 `requirements.txt`），离线排版，不联网。
- 一个中文字体文件（TrueType `.ttf` 或 `.ttc`）。字体不随仓库分发，避免版权问题。

字体按以下顺序自动查找，第一个可用的生效：

1. 命令行 `--font` 指定的路径。
2. 环境变量 `AMAZON_ANALYST_FONT`。
3. 常见系统路径：Windows 的微软雅黑、等线、黑体、宋体；macOS 的苹方；Linux 的文泉驿字体。

比例字宽的中文字体（微软雅黑、苹方）排在宋体前面，因为宋体的 ASCII 字形按全角宽度排布，`20,000.00` 这类数字在正文里会被拉开成明显的空档。使用宋体时表格数字仍然正确，只是观感偏差。

都不存在时脚本会报错并列出每个候选的失败原因。可用字体必须是 TrueType 轮廓；CFF／OpenType 轮廓（部分 `.otf`）无法被当前渲染器嵌入。

## 报告 JSON 结构

```json
{
  "title": "标题",
  "subtitle": "副标题（可选，可用 \n 换行）",
  "summary": ["决策摘要条目，按顺序编号"],
  "sections": [
    {
      "title": "章节标题",
      "page_break": true,
      "paragraphs": ["正文段落"],
      "bullets": ["需要编号的条目"],
      "table": {"columns": ["列1", "列2"], "rows": [["值", "值"]]},
      "chart": {"title": "图标题", "unit": "USD", "labels": ["A"], "values": [1.0], "source": "来源说明"},
      "image": {"path": "相对或绝对路径", "caption": "图注", "source": "来源说明"}
    }
  ],
  "sources": ["数据与计算说明"]
}
```

约束：

- `title`、每个 `section.title` 必填且非空；`sections` 至少一个。
- 表格 1–8 列，每行列数与列名数一致；单元格只能是字符串或有限数字，`NaN`、`Infinity`、`null` 一律拒绝。
- 图表 `labels` 与 `values` 等长且非空；缺失值必须写成"不可计算"之类的说明文字，不能塞 `null` 让它显示成 0。
- `image.path` 只接受本地文件；含 `://` 的地址会被拒绝，避免渲染时联网。
- 正文按纯文本处理，HTML 标记会被转义，不会变成链接或样式。

## 命令

```bash
python scripts/render_report.py report.json output.pdf
```

可选 `--font`。输入输出路径相同时报错。排版失败时不会留下半成品文件：先写临时文件，成功后才替换目标。

## 排版约定

- A4，页边距左右 18mm，页脚含项目名与页码。
- 首页与后续页使用同一页眉页脚，不额外加封面页。
- 章节 `page_break: true` 强制新起一页；长表格按行跨页并重复表头。
- 图表为横向条形，负值用橙色向右反方向绘制，并带零线；行数多时自动续页。
- 图片按页宽与 155mm 高度等比缩放，图注与来源跟随图片保持在同一页。

## 交付前检查

1. **能打开**：`pypdf` 读取页数与元数据，不报错。
2. **文字可检索**：抽取文本后中文正常显示，不是乱码或方框。
3. **数值对账**：图表与表格的数字和正文一致，四舍五入差异不超过展示精度。
4. **分页完整**：逐页确认表头重现、长表未被截断、图表与脚注未被裁切。
5. **口径可追溯**：`sources` 里能定位到文件、工作表、字段、筛选范围与公式。

逐页目视检查建议先把 PDF 转成图片再看；脚本本身只保证结构完整，不判断内容是否成立。

## 无法生成 PDF 时

先确认是缺 `reportlab`、缺字体，还是 JSON 结构不合规，把具体错误说清楚。可以交付 Markdown 或 HTML 作为替代，但不要把它称为 PDF，也不要跳过逐页检查就宣称已完成。
